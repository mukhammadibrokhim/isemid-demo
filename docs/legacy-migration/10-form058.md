### 2b. `status` → yangi `FormStatus`  ✅ HAL QILINDI

Legacy: `NOT_APPROVED, NEW, SENT, RECEIVED, CARD_LINKED, APPROVED_PENDING, APPROVED, CANCELED`
Yangi: `SENT, ACCEPTED, CARD_LINKED, APPROVED, CANCELED`

| legacy | → taklif | izoh |
|---|---|---|
| `NEW` | `SENT` | yangi'da "draft" holati yo'q — minimal `SENT` |
| `SENT` | `SENT` | 1:1 |
| `RECEIVED` | `ACCEPTED` | qabul qilingan |
| `APPROVED_PENDING` | `ACCEPTED` | ⚠️ yoki `CARD_LINKED`? |
| `CARD_LINKED` | `CARD_LINKED` | 1:1 |
| `APPROVED` | `APPROVED` | 1:1 |
| `CANCELED` | `CANCELED` | 1:1 |
| `NOT_APPROVED` | `CANCELED` | ⚠️ rad etilган forma — `CANCELED` ga? `cancel_reason` = eski `not_approve_comment` |

### 2c. `source` (yangi NN, varchar 64)  ⚠️ QAROR

Qaror: `YKEM` → `MANUAL`, `DMED` → `DMED`, boshqa/NULL → `MANUAL`.
**⚠️ Legacy'da YKEM/DMED qiymati QAYSI ustunда saqlanган?** `form058` DDL'ида
aniq `source`-ga o'xshash ustun yo'q. Ehtimol nomzodlar:
- `journal_form_code` (agar unда YKEM/DMED bo'lsa)
- boshqa jadval / audit
Aniqlansin — keyin `CASE` yoziladi. Hozircha barcha qatorlar `'MANUAL'`.

### 2d. `has_linked_cards` (yangi NN)

```
has_linked_cards := EXISTS (SELECT 1 FROM public.card c WHERE c.form058_id = form058.id)
```

### 2e. Denormalizatsiya qilingan patient maydonlari (yangi NN)  ⚠️ QAROR

Yangi `form058` bularni denormalizatsiya qilib saqlaydi. `public.patient`

| `patient_birth_date` | `patient.birth_date` | |

| `patient_pinfl` (varchar14) | `pt_identifier.value` WHERE `type_code = ?` (PINFL) | topilmasa NULL |

### 2f. `location_*` maydonlari (yangi, nullable)  ⚠️ QAROR

Yangi `location_region_code`, `location_district_code`, `location_neighborhood_code`,
`location_address` — legacy `form058` da mos ustun **yo'q** (`location_id` →
`fm058_location` faqat lat/long/matn beradi).

Taklif: `NULL` qoldirish (legacy manba yo'q). YOKI bemorning doimiy manzilидан
(`public.pt_address` WHERE `type='PERMANENT'`) olib to'ldirish — ⚠️ qaror.

### 2g. Approve/cancel audit maydonlari

Yangi: `canceled_by_id`, `canceled_at`, `approved_by_id`, `approved_organization_id`,
`approved_at`, `approved_full_name`, `approved_org_uuid`.
Legacy `form058` da bular **yo'q** → hammasi `NULL`.
(Agar `status IN (APPROVED, CANCELED)` bo'lsa ham audit qiymatlar yo'qligi
qabul qilinadi — ⚠️ tasdiqlash yoki `updated_at`/`updated_by_id` dan taxminlash.)

### 2h. `assigned_card_id` — OXIRIDA UPDATE

`card` ko'chгач:
```
UPDATE public2.form058 f
SET assigned_card_id = c.id
FROM public.card c
WHERE c.form058_id = f.id
  AND c.status IN ('APPROVED', 'ACCEPTED_BY_USER', 'COMPLETED');   -- ⚠️ qaysi statusdagi card "assigned" hisoblanadi?
```
⚠️ Legacy'da "assigned card" tushunchasi qanday aniqlangan? (bitta form → bitta assigned card?)

## 3. ⚠️ Ushbu modul uchun ochiq qarorlar

1. **`source` manba ustuni** — YKEM/DMED legacy'да qayerда? (2c)
2. **`status` mapping** — `NEW→SENT`, `APPROVED_PENDING→ACCEPTED`, `NOT_APPROVED→CANCELED` to'g'rimi? (2b)
3. **`not_approve_comment` → `cancel_reason`** — semantik mos keladimi? (2a)
4. **`patient_nnuzb` / `patient_pinfl`** — `pt_identifier.type_code` qaysi qiymatlar? NNUZB topilmasa (NN!) nima? (2e)
5. **`location_*_code`** — NULL qoldirilsinmi yoki `pt_address` dan? (2f)
6. **NN sana/matn ustunlari** (`disease_date`, `first_visit_date`, `visit_date`, `initial_report_date_time`, `disease_place`, `notifier_full_name`) legacy NULL qatorlar soni + default. (2a)
7. **`disease_place`** (yangi NN varchar512) — legacy'да `disease_place_code` bor, lekin matnli `disease_place` yo'q. Nima yoziladi? (`disease_place_code` ning nomi? `ref_catalog` dan?) ⚠️
8. **`sender/receiver_organization_id` NN** — legacy NULL qatorlar.
9. **`assigned_card_id`** aniqlash mantig'i. (2h)
